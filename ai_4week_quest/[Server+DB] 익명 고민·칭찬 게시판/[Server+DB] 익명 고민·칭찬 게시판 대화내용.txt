하버스쿨 AI 교육 · 4주차 [Server+DB] 퀘스트
익명 고민·칭찬 게시판 — 제작 대화 내용
======================================================================

[과제 목표]
Server + DB(Supabase)를 조합해 익명 고민/칭찬 게시판 제작
1. 익명으로 글 작성 (고민/칭찬/응원 카테고리 선택)
2. 글에 공감 버튼 (공감 수 +1 UPDATE)
3. 최신순 / 공감순 정렬 조회
4. 모든 데이터를 Supabase DB에 저장
핵심 구조:
  [글 작성(카테고리,내용)] → [Server] → DB 저장 → [목록 조회]
  [공감 클릭] → [Server] → DB UPDATE(likes = likes + 1) → 화면 반영


----------------------------------------------------------------------
1) 폴더 생성
----------------------------------------------------------------------
나: [Server+DB] 익명 고민/칭찬 게시판을 만들어줘.

AI: 기존 형제 프로젝트([Server+DB] 냉장고 재료 & 레시피 관리앱)와 동일한
   위치(ai_4week_quest)·네이밍 컨벤션으로 폴더를 생성하고, 그 프로젝트의
   구조/주석 스타일/응답 형식을 그대로 따르기로 했습니다.


----------------------------------------------------------------------
2) 두 에이전트 분업 (서버 / 프론트)
----------------------------------------------------------------------
나: single-react-dev 와 single-server-specialist 둘이 작업.

AI: 분업의 핵심은 "서로 안 맞는 것"을 막는 것이라, 먼저 API 계약(contract)을
   확정해 양쪽에 동일하게 전달하고 서로 다른 파일만 건드리게 했습니다.
   - 테이블: posts(id, category, content, likes, created_at)
   - GET /api/posts?sort=latest|likes  (최신순/공감순)
   - POST /api/posts {category, content}
   - POST /api/posts/:id/like          (핵심: likes = likes + 1 UPDATE)
   - DELETE /api/posts/:id
   - 응답 형식: { success, data, message } 로 통일
   - 카테고리는 '고민'|'칭찬'|'응원' 문자열만 서버에서 허용

   두 에이전트를 동시에 실행했으나, 백그라운드 서브에이전트는 "파일 쓰기
   (Write) 권한" 프롬프트를 띄울 수 없어 양쪽 모두 파일 저장이 막혔습니다.
   그래서 두 에이전트가 확정한 설계·계약을 그대로 받아 메인(저)이 직접
   파일을 작성하고 끝까지 검증했습니다.

   [생성 파일]
   - server.js     : Express + pg(Pool) + dotenv, 테이블 자동 생성
   - index.html    : CDN React + Tailwind 단일 파일 게시판
   - package.json  : express / pg / dotenv
   - .env.example  : DATABASE_URL, PORT (비밀번호 자리표시자)
   - vercel.json   : 배포 설정
   - .gitignore    : node_modules / .env / .vercel


----------------------------------------------------------------------
3) 개념 설명 (공감 버튼 = DB UPDATE)
----------------------------------------------------------------------
나: 공감 버튼이 어떻게 동작하는지 이해되게 설명해.

AI: 공감의 핵심은 DB의 UPDATE입니다.
   1) 사용자가 ❤️ 버튼 클릭
   2) 프론트가 서버에 POST /api/posts/:id/like 요청
   3) 서버가 DB에 UPDATE posts SET likes = likes + 1 WHERE id = $1 실행
   4) 갱신된 행(늘어난 likes)을 다시 돌려줌
   5) 프론트가 그 값으로 해당 글만 교체 → 숫자가 +1 됨
   새로고침해도 숫자가 유지되는 이유 = DB에 저장됐기 때문입니다.


----------------------------------------------------------------------
4) 창의성 보너스 — 추가 기능 4종 (사용자 선택)
----------------------------------------------------------------------
나: 창의성 점수를 받을만한 추가 아이디어를 작성하고 내가 고르게 해줘.

AI: 채점 기준(창의성 5pt: 답글/태그 필터/베스트 모아보기 등 개성)을 보고
   현재 코드 위에 바로 얹을 수 있는 4가지를 제안했고, 4개 모두 선택받아
   전부 구현했습니다.

   ① 익명 답글(댓글) 기능
      - comments 테이블 추가 (post_id로 posts와 1:N 관계,
        글 삭제 시 ON DELETE CASCADE로 답글도 함께 삭제)
      - GET/POST /api/posts/:id/comments
      - DB의 "두 번째 테이블 + 관계"까지 보여주는 가장 강력한 어필
   ② 카테고리 탭 필터
      - 전체 / 💭고민 / 👏칭찬 / 💪응원 탭, 각 탭에 글 개수 뱃지
   ③ 🏆 베스트 게시글 (명예의 전당)
      - 공감(❤️) TOP 3을 상단에 금·은·동으로 고정, 클릭 시 해당 글로 스크롤
   ④ 여러 감정 리액션
      - ❤️공감 / 🤗위로 / 🔥응원 버튼을 각각 카운트
      - posts에 hug, cheer 컬럼 추가, POST /api/posts/:id/react {type}
      - type은 화이트리스트로 컬럼명을 확정해 SQL 인젝션 방지


----------------------------------------------------------------------
5) 실제 동작 검증 (Supabase 연결 후 엔드투엔드)
----------------------------------------------------------------------
나: 열어서 확인. 비밀번호는 냉장고 만들 때 썼던 걸 가져와서 써.

AI: 냉장고 프로젝트의 .env(같은 Supabase 프로젝트)를 복사해 서버를 실행하고
   (포트 3000이 사용 중이라 3100으로 기동) curl로 전 기능을 검증했습니다.
   - 글 작성(고민/칭찬/응원) → 201 + DB 저장 ✅
   - 공감 likes +1 UPDATE → 3까지 정확히 증가 ✅
   - 리액션 hug/cheer +1 ✅
   - 잘못된 리액션 타입 → 400 거부(인젝션 방어 동작) ✅
   - 답글 작성/조회 ✅
   - 공감순 정렬(likes DESC) ✅
   - 잘못된 카테고리 → 400 거부 ✅
   - 글 삭제 시 답글 CASCADE 삭제 ✅
   - 정적 페이지 HTTP 200, 브라우저로 정상 렌더 확인 ✅
   첫 실행 시 posts·comments 테이블이 자동 생성됨을 확인했습니다.
