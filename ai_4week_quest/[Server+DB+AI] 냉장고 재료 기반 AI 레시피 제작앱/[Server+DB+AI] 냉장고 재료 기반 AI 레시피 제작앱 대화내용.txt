하버스쿨 AI 교육 · 4주차 [Server+DB+AI] 퀘스트
냉장고 재료 기반 AI 레시피 제작앱 — 제작 대화 내용
======================================================================

[과제 목표]
Server + DB(Supabase) + AI 를 조합해, 냉장고 재료를 기반으로
AI가 레시피를 자동 생성해주는 앱 제작.
1. 이전 퀘스트의 재료 관리 앱을 "기반"으로 시작
2. 저장된 재료로 AI가 레시피 자동 생성
3. AI가 생성한 레시피를 DB에 저장
4. 저장된 레시피를 목록으로 조회

핵심 구조:
  [DB에서 재료 조회] → [Server: AI API 호출] → [레시피 자동 생성]
  → [DB에 저장] → [레시피 목록에 표시]


----------------------------------------------------------------------
1) 무료 AI API 선택
----------------------------------------------------------------------
나: 이전에 만든 걸 기반으로 만들어줘. 근데 AI API를 구매하기 싫은데
   무료로 쓸 수 있는 곳 알아?

AI: 카드 등록 없이 무료로 쓸 수 있는 곳을 안내:
   - Google Gemini (AI Studio) : 카드 불필요, 무료 한도 넉넉, 한국어 잘함 (추천)
   - Groq : 가입만으로 무료, 매우 빠름
   - OpenRouter : 일부 무료 모델
   → 사용자가 Google Gemini 선택.


----------------------------------------------------------------------
2) 이전 앱을 기반으로 복사 + AI 기능 추가
----------------------------------------------------------------------
나: single-react-dev / single-server-specialist 필요하면 같이 제작해.

AI: 이전 [Server+DB] 냉장고 앱 폴더를 통째로 복사해
   "[Server+DB+AI] 냉장고 재료 기반 AI 레시피 제작앱" 폴더를 만들었습니다.
   (ingredients 테이블, Supabase 연결 .env 그대로 재활용 — 처음부터 다시 X)
   ※ 두 에이전트는 이번에도 파일 쓰기 권한이 막혀, 그 설계 역할을
     메인(저)이 직접 수행했습니다.

   [서버/DB 변경 — server.js]
   - recipes 테이블에 컬럼 추가: cook_time(조리시간), difficulty(난이도),
     source('manual' | 'ai').  기존 DB 호환용 ALTER TABLE ... ADD COLUMN IF NOT EXISTS.
   - 신규 엔드포인트 POST /api/recipes/generate
     · DB에서 재료 목록 조회
     · 모드(간단요리/다이어트/야식/푸짐한)별 프롬프트 구성
     · Gemini 호출(REST, Node 내장 fetch — 추가 패키지 없음)
     · responseSchema로 JSON(title, ingredients, steps, cookTime, difficulty) 강제
     · 생성된 레시피 "초안" 반환 (저장은 사용자가 선택)
   - POST /api/recipes 확장: cookTime, difficulty, source 도 함께 저장
   - API 키는 .env의 GEMINI_API_KEY에서 읽음 (코드 하드코딩 X)

   [프론트 변경 — index.html]
   - 🤖 AI 셰프 패널 추가: 모드 선택 → "✨ AI 레시피 생성" →
     초안 미리보기(조리시간·난이도 뱃지) → "💾 저장 / 🔄 다시 생성"
     (사용자가 선택하는 흐름)
   - 레시피 카드에 🤖 AI / ⏱️조리시간 / 📊난이도 뱃지 표시
   - 냉장고 디자인 + "지금 만들 수 있는 요리" 매칭 기능은 그대로 유지


----------------------------------------------------------------------
3) 무료 키 발급 & 트러블슈팅
----------------------------------------------------------------------
나: 키 있던 거 써도 됨?  (AIzaSy... 기존 키)

AI: 키 인증은 됐으나(401/403 아님), 그 키가 묶인 프로젝트에서
   gemini-2.0-flash의 무료 한도가 0(limit:0)으로 잡혀 429 발생.
   → 보통 예전에 결제 연결됐던 프로젝트의 키에서 생기는 현상.

나: 키 죽은 거임? 다시 받을게. → (새 키 발급) 받아옴.

AI: 새 키로 사용 가능한 모델 목록 조회 → gemini-2.5-flash 가
   무료로 정상 작동(HTTP 200) 확인.
   → .env에 새 키 적용 + 서버 모델을 gemini-2.5-flash 로 변경.


----------------------------------------------------------------------
4) 실제 동작 검증 (전체 흐름)
----------------------------------------------------------------------
AI: 실제 AI 레시피 생성 테스트 (mode: 다이어트)
   → "저지방 돼지고기 두부 김치볶음" 생성
     (재료: 돼지고기·두부·김치·양파·당근·대파·고추장·간장,
      조리시간: 약 25분, 난이도: 보통)
   → DB 저장(POST /api/recipes, source:'ai') → HTTP 201
   → 목록 조회 시 🤖 AI 뱃지로 표시 확인.

   검증 결과:
   ✅ DB 재료 조회 → ✅ Gemini 호출 → ✅ 레시피 생성
   → ✅ DB 저장(source=ai) → ✅ 목록 표시   (전 과정 통과)

[최종 결과물]
======================================================================
- 스택   : Node.js + Express + pg(Supabase PostgreSQL) + dotenv
           + Google Gemini API(gemini-2.5-flash, 무료, REST)
           / CDN React 18 + Babel 7.23.5 + Tailwind (단일 index.html)
- 테이블 : ingredients(id, name, category, expiry_date, created_at)
           recipes(id, title, ingredients, steps, cook_time, difficulty,
                   source, created_at)
- API    : 재료 GET/POST/DELETE,
           레시피 GET/POST/DELETE,
           POST /api/recipes/generate  (DB 재료 → Gemini → 레시피 생성)
- AI 흐름: DB 재료 조회 → 모드별 프롬프트 → Gemini 생성 →
           사용자 저장 선택 → DB 저장(source:'ai') → 목록 표시
- 기능   : 재료 CRUD, 유통기한 관리, "지금 만들 수 있는 요리" 매칭,
           AI 레시피 자동 생성(모드: 간단요리/다이어트/야식/푸짐한),
           조리시간·난이도 저장, 저장/다시생성 선택
- 디자인 : 냉장고 형태 + AI 셰프 패널 + 자석 메모판

[실행 방법]
  cd "[Server+DB+AI] 냉장고 재료 기반 AI 레시피 제작앱"
  cp .env.example .env
  # .env 에 DATABASE_URL(Supabase) + GEMINI_API_KEY 입력
  #   - Gemini 무료 키: https://aistudio.google.com/apikey (새 프로젝트로 발급)
  npm install
  npm start
  → 브라우저에서 http://localhost:3000 접속
  → 🤖 AI 셰프에서 모드 선택 → 생성 → 저장
