하버스쿨 AI 교육 · 4주차 [Server+DB] 퀘스트
냉장고 재료 & 레시피 관리앱 — 제작 대화 내용
======================================================================

[과제 목표]
Server + DB(Supabase)를 조합해 냉장고 재료와 레시피를 저장/관리하는 앱 제작
1. 냉장고 재료 등록/삭제
2. 레시피 직접 작성/저장 (요리명, 재료, 조리법)
3. 재료·레시피 목록 조회
4. 모든 데이터를 Supabase DB에 저장
핵심 구조:
  [재료 등록/삭제] → [Server] → DB 저장 → [재료 목록 조회]
  [레시피 작성]    → [Server] → DB 저장 → [레시피 목록 조회]


----------------------------------------------------------------------
1) 폴더 생성
----------------------------------------------------------------------
나: "[Server+DB] 냉장고 재료 & 레시피 관리앱" 폴더를 제작해줘.

AI: 기존 [DB] 메모장 앱과 동일한 위치(ai_4week_quest)에, 같은
   "[프리픽스] 이름" 네이밍 컨벤션으로 폴더를 생성했습니다.


----------------------------------------------------------------------
2) 두 에이전트 분업 (서버 / 프론트)
----------------------------------------------------------------------
나: single-react-dev 와 single-server-specialist 둘이 같이 만들어라.
   서버 스페셜리스트는 서버랑 DB 구축하고, 리액트 데브는 관리앱을 그려라.

AI: 분업의 핵심은 "서로 안 맞는 것"을 막는 것이라, 먼저 API 계약(contract)을
   확정해 양쪽에 동일하게 전달했습니다.
   - 테이블: ingredients(id,name,category,created_at),
             recipes(id,title,ingredients,steps,created_at)
   - GET/POST /api/ingredients, DELETE /api/ingredients/:id
   - GET/POST /api/recipes,      DELETE /api/recipes/:id
   - 응답 형식: { success, data, message } 로 통일

   두 에이전트를 동시에 실행했으나, 서브에이전트가 "파일 쓰기(Write) 권한"이
   막혀 파일을 생성하지 못했습니다. 그래서 두 에이전트의 설계를 그대로 받아
   메인(저)이 직접 6개 파일을 작성했습니다.

   [생성 파일]
   - server.js      : Express + pg(Pool) + dotenv, 6개 CRUD API, 테이블 자동 생성
   - index.html     : CDN React + Tailwind 단일 파일 관리앱
   - package.json   : express / pg / dotenv
   - .env.example   : DATABASE_URL, PORT (비밀번호 자리표시자)
   - vercel.json    : 배포 설정
   - .gitignore     : node_modules / .env / .vercel


----------------------------------------------------------------------
3) 개념 설명 (사용자 이해용)
----------------------------------------------------------------------
나: 내가 이해되도록 설명해.

AI: 앱은 3개의 층으로 나뉩니다 (식당 비유).
   - 프론트엔드(index.html) = 손님이 보는 메뉴판/주문서 (화면)
   - 서버(server.js)        = 주방 직원 (요청을 받아 DB에 넣고 꺼냄)
   - DB(Supabase)           = 식자재 창고 (데이터 영구 저장)
   흐름: 화면에서 재료 추가 → fetch('/api/ingredients') → 서버 INSERT
        → Supabase 저장 → 화면이 목록 다시 불러와 갱신.


----------------------------------------------------------------------
4) Supabase 비밀번호 / .env 설정
----------------------------------------------------------------------
나: 비밀번호 찾는 법 알려줘 → 메모장 앱 .env 재활용하자.

AI: Supabase는 DB 비밀번호를 다시 보여주지 않으므로(재설정만 가능),
   가장 쉬운 방법은 이전 [DB] 메모장 앱의 .env를 재활용하는 것.
   메모장 앱의 .env를 새 앱 폴더로 복사했습니다.


----------------------------------------------------------------------
5) 실행 & DB 저장 검증
----------------------------------------------------------------------
나: 실행해봐 / DB에 잘 저장되는지 확인시켜줘.

AI: 서버를 켜고 6개 API를 모두 테스트했습니다.
   - 재료 등록(POST) → 201
   - 레시피 저장(POST) → 201 (조리법 줄바꿈 유지)
   - 목록 조회(GET) → DB에서 꺼내옴
   - 삭제(DELETE) → 정상

   추가로 API를 거치지 않고 PostgreSQL에 직접 SELECT 쿼리를 날려,
   원격 Supabase 서버 IP에서 데이터가 응답되는 것을 확인했습니다.
   → 내 PC가 아닌 클라우드 DB에 실제 저장됨을 증명.


----------------------------------------------------------------------
6) 화면이 안 뜨는 문제 → 원인 발견 & 해결
----------------------------------------------------------------------
나: 야 안뜬다 (흰 화면).

AI: 서버·CDN·코드(JSX 컴파일) 모두 정상인데 화면만 흰색.
   화면에 에러 표시 장치를 넣어 원인을 잡았습니다.

   [원인] Uncaught SyntaxError: Cannot use import statement outside a module
   → @babel/standalone 최신(7.26.x) 버전의 text/babel 변환 버그.
     (curl·문법검사는 통과하는데 브라우저에서만 깨지는 함정)

   [해결] Babel을 안정 버전 7.23.5 로 고정 + React 18.3.1 핀.
   새로고침 후 화면 정상 표시.


----------------------------------------------------------------------
7) 샘플 데이터 투입
----------------------------------------------------------------------
나: 재료 10개, 레시피 5개 임의로 넣어줘.

AI: 양파·당근·대파·감자·돼지고기·계란·우유·버터·고추장·간장(재료 10) +
   감자채볶음·계란말이·제육볶음·감자버터구이·간장계란밥(레시피 5)을
   API로 등록. 전부 DB 저장 확인.


----------------------------------------------------------------------
8) 기능 추가 (AI 제외, 2가지) + 냉장고 디자인
----------------------------------------------------------------------
나: 참신한 기능 추천해줘 → 3개 중 AI(3번)는 빼고 2개만.
   그리고 UI를 냉장고 형태 디자인으로 바꿔줘.

AI: [추가 기능]
   (1) 지금 만들 수 있는 요리 — 레시피 재료 vs 냉장고 재료 대조
       → "✅ 지금 만들 수 있어요!" / "⚠️ N개 부족" 뱃지 (프론트 로직)
   (2) 유통기한 관리 — ingredients 테이블에 expiry_date 컬럼 추가
       → 재료 추가 시 날짜 선택, D-day 뱃지(만료 빨강/임박 주황/여유 회색),
         임박순 정렬, 냉동고 칸 "빨리 드세요" 알림 (DB+서버+프론트)
       ※ AI(Claude API)는 키가 필요해 제외함.

   [냉장고 디자인]
   - 왼쪽 = 진짜 냉장고 모양(금속 프레임 + 세로 손잡이)
     · 위 냉동고 칸 = 유통기한 알림
     · 가운데 냉장실 = 카테고리별 유리 선반 위 재료 칩
     · 아래 야채칸 서랍 = 재료 추가 폼
   - 오른쪽 = 자석 메모판(포스트잇 레시피, 자석 압정, 살짝 기울어짐)

   server.js: CREATE TABLE에 expiry_date DATE + 기존 DB 호환용
   ALTER TABLE ... ADD COLUMN IF NOT EXISTS 추가, POST에서 expiryDate 처리.
   문법검사 + JSX 컴파일 + DB 컬럼 동작(두부 D-2 저장) 모두 통과.


----------------------------------------------------------------------
9) 재료/레시피 추가 + 전부 제작 가능하게
----------------------------------------------------------------------
나: 냉장고에 재료 넣고, 그 재료로 만들 수 있는 레시피 3개 더 추가해줘.

AI: 김치·양배추·애호박·마늘·식용유·소금·밥 추가(유통기한 다양하게)
   + 레시피 3개(두부김치볶음·감자채전·양배추계란볶음밥) 추가 — 모두 ✅.

나: 부족한 후추·설탕도 넣어줘.

AI: 후추·설탕 추가 → 레시피 8개 전부 "✅ 지금 만들 수 있어요" 달성.
   최종: 재료 20개 / 레시피 8개 / 지금 만들 수 있는 요리 8개. 전부 DB 저장.

[최종 결과물]
======================================================================
- 스택      : Node.js + Express 4 + pg(Supabase PostgreSQL) + dotenv
              / CDN React 18 + Babel 7.23.5 + Tailwind (단일 index.html)
- 테이블    : ingredients(id, name, category, expiry_date, created_at)
              recipes(id, title, ingredients, steps, created_at)
- API       : 재료 GET/POST/DELETE, 레시피 GET/POST/DELETE (응답 {success,data,message})
- 기능      : 재료 CRUD, 레시피 CRUD, 목록 조회,
              유통기한 D-day 관리, "지금 만들 수 있는 요리" 매칭
- 디자인    : 냉장고 형태 (냉동고/냉장실/야채칸 + 자석 메모판)
- 데이터    : 재료 20개 / 레시피 8개, 모두 Supabase DB 영속 저장

[실행 방법]
  cd "[Server+DB] 냉장고 재료 & 레시피 관리앱"
  cp .env.example .env   # DATABASE_URL에 Supabase 비밀번호 입력
  npm install
  npm start
  → 브라우저에서 http://localhost:3000 접속
