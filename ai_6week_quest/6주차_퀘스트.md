# 🐹 고블린 (미니 퀘스트)

## G1. [Payment] 내 쇼핑몰에 100원 결제 성공시키기 (테스트 키) — 15pt (+5)
> 🎯 **토스페이먼츠 테스트 키**로 내 쇼핑몰에서 100원짜리 결제를 성공시키기

**⚠️ 전제**: 5주차 `[Auth + DB] 쇼핑몰(결제 제외)` 완료 · 토스페이먼츠 개발자센터 테스트 키(`test_ck_...`) 발급

**설명**
5주차에 만든 쇼핑몰에 토스페이먼츠 결제 위젯을 붙이고, 테스트 키로 100원짜리 상품을 실제로 결제 성공까지 완료한다. 결제 승인 후 DB에 주문 기록이 남는 것까지 확인.

**핵심 플로우**: `위젯 표시 → 결제 요청 → 승인 API 호출(서버) → DB 주문 저장`

**팁**
- 실제 돈이 나가는 게 아니라 **테스트 환경**. 테스트 키(`test_ck_...`) 발급받아 사용
- 승인 API 호출은 **반드시 서버에서** — Secret Key 노출 금지
- 개발자도구 Network 탭에서 `/confirm` 응답이 **200 OK**로 오는지 확인
- 카드 번호는 공식 문서의 **테스트 카드번호** 사용

**보너스 (+5pt)**: 결제 완료 후 **주문 상세 페이지**를 만들어 결제 내역(상품명/금액/주문번호) 표시
> ⚠️ 반드시 위 항목을 다 완료 & Commit 한 뒤 보너스 추가

## G2. 쇼핑몰: 마이페이지 — 10pt (+5)
> 🎯 내 쇼핑몰에 **마이페이지**를 붙여 내가 주문한 내역을 한눈에

**설명**
로그인한 사용자가 자기 **주문 내역(상품명 / 금액 / 주문일 / 주문번호)**을 볼 수 있는 마이페이지 추가. 핵심은 **본인 주문만** 볼 수 있게 권한 제어하는 것.

**팁**
- 마이페이지는 **Todo 앱과 구조가 똑같다** — `user_id` 필터로 본인 데이터만 가져오면 끝
- `orders` 조회 시 **반드시** `where user_id = 현재 로그인 user_id`
- 주문 내역은 **최신순**(`paid_at DESC`)
- 주문번호가 길면 앞 8자리만 표시(`#ABC12345...`)
- 주문 0건일 때 **빈 상태 화면**("아직 주문 내역이 없어요")도 잊지 말기

**보너스 (+5pt)**: **주문 상세 페이지**에서 각 주문 안의 상품들(수량/단가/합계) 표시
> ⚠️ 반드시 위 항목을 다 완료 & Commit 한 뒤 보너스 추가

# 📜 퀘스트

## 1. [Payment+File] 쇼핑몰 완성 (이미지 + 결제 + 마이페이지)
> 🎯 5주차 쇼핑몰에 **이미지 업로드 + 결제 + 마이페이지**를 붙여 진짜 서비스로 완성
> 💡 G1·G2 고블린을 하나로 합치고 **이미지 업로드**까지 얹은 종합 퀘스트

**⚠️ 전제**: 5주차 `[Auth + DB] 쇼핑몰(결제 제외)` 완료 · 토스페이먼츠 테스트 키(`test_ck_...`) 미리 발급

**미션**
- **Part 1 — 상품 이미지 업로드(관리자 기능)**
  - ImageKit으로 상품 이미지 업로드 후 DB에 URL 저장
  - 상품 등록 화면에서 드래그앤드롭 또는 파일 선택으로 첨부
  - 상품 목록에 업로드된 이미지가 실제로 뜨는지 확인
- **Part 2 — 결제 플로우**
  - 장바구니 → 결제 페이지 이동 → 토스페이먼츠 결제 위젯(테스트 키)
  - 결제 승인 API는 **반드시 서버에서** 호출 (Secret Key 노출 금지)
  - 주문 정보를 DB `orders` 테이블에 저장
- **Part 3 — 마이페이지**
  - 로그인 사용자의 주문 내역 조회 (상품명/금액/주문일/주문번호)
  - **본인 주문만** 볼 수 있게 권한 제어
- **Part 4 — 배포**
  - Vercel 배포 & URL 제출 · 환경변수(토스 Secret Key, ImageKit Key)는 Vercel 대시보드에 등록

**핵심 구조**
```
[관리자 상품 등록] → ImageKit 이미지 업로드 → DB에 URL 저장
[장바구니] → [토스 결제 위젯] → 서버 승인 API → DB orders 저장
[마이페이지] → 본인 user_id로 orders 조회 → 주문 내역 렌더링
```

**DB 테이블 구조(참고)**
```
products:    id, name, price, image_url, description
orders:      id, user_id, total_price, paid_at, status
order_items: id, order_id, product_id, quantity, price
```

**제출물**: 배포 URL(Vercel) · GitHub 링크 · 앱 스크린샷(상품목록(이미지)→장바구니→결제→마이페이지) · **테스트 결제 성공 화면**

**포인트**: 기본 10(이미지+결제+마이페이지 동작 & 배포) / 에이전트 활용 5 / 창의 5(결제완료 이메일·주문상태 관리·상품검색·재고관리 등) / 공유 5 → **올클리어 25pt**

**팁**
- 결제 플로우는 한 번에 성공하기 어렵다 — **테스트 카드로 여러 번**, 네트워크 탭 보는 습관
- 에러 메시지를 에이전트에 그대로 붙여넣으면 대부분 해결
- 토스 공식 "결제 연동 가이드" 먼저 훑기 · 결제성공→주문저장→리다이렉트 **순서**가 꼬이면 주문 유실
- 이미지는 공개 접근이 필요하니 Supabase Storage보다 **ImageKit**이 편함
- 마이페이지는 5주차 "장바구니" 패턴 그대로 — `user_id` 필터만 걸면 끝

## ⚠️ 보안 핵심 (결제 트랙 공통)
- 토스페이먼츠 **Secret Key는 절대 프론트엔드에 노출 금지** → 승인 API는 **서버에서만** 호출

- 결제는 테스트 키(`test_ck_...`) + 테스트 카드로 — 실제 결제 아님
