## G1. [Payment] 내 쇼핑몰에 100원 결제 성공시키기 (테스트 키) — 15pt (+5)
> 🎯 **토스페이먼츠 테스트 키**로 내 쇼핑몰에서 100원짜리 결제를 성공시키기

**설명**
5주차에 만든 쇼핑몰(결제 기능 제외)에 토스페이먼츠 결제 위젯을 붙이고, 테스트 키로 100원짜리 상품을 실제로 결제 성공까지 완료한다. **결제 승인 후 DB에 주문 기록이 남는 것까지** 확인.

**팁**
- 실제 돈이 나가는 게 아니라 **테스트 환경** — 토스페이먼츠 개발자 센터에서 테스트 키(`test_ck_...`) 발급받아 사용
- 결제 플로우: **위젯 표시 → 결제 요청 → 승인 API 호출 → DB 주문 저장**
- 승인 API 호출은 **반드시 서버에서** (Secret Key 노출 금지)
- 개발자도구 Network 탭에서 `/confirm` 응답이 **200 OK**로 오는지 확인
- 카드 번호는 공식 문서의 **테스트 카드번호** 사용

**보너스 (+5pt)**: 결제 완료 후 **주문 상세 페이지**를 만들어 결제 내역(상품명 / 금액 / 주문번호) 표시
> ⚠️ 반드시 위 항목을 다 완료 & Commit 한 뒤 보너스 추가

## G2. 쇼핑몰: 마이페이지 — 10pt (+5)
> 🎯 내 쇼핑몰에 **마이페이지**를 붙여 내가 주문한 내역을 한눈에

**설명**
결제가 끝나면 "내가 뭘 샀더라?" 싶어진다. 로그인한 사용자가 자기 **주문 내역(상품명 / 금액 / 주문일 / 주문번호)**을 볼 수 있는 마이페이지를 추가. 핵심은 **본인 주문만** 볼 수 있게 권한 제어하는 것.

**팁**
- 마이페이지는 **Todo 앱과 구조가 똑같다** — `user_id` 필터로 본인 데이터만 가져오면 끝
- `orders` 조회 시 **반드시** `where user_id = 현재 로그인 user_id`
- 주문 내역은 **최신순**(`paid_at DESC`)
- 주문번호가 길면 앞 8자리만 표시(`#ABC12345...`)
- 주문 0건일 때 **빈 상태 화면**("아직 주문 내역이 없어요")도 잊지 말기

**보너스 (+5pt)**: **주문 상세 페이지**에서 각 주문 안의 상품들(수량 / 단가 / 합계) 표시
> ⚠️ 반드시 위 항목을 다 완료 & Commit 한 뒤 보너스 추가

**설명**
"왜 이 앱을 만드는가?"를 **한 문단(3~5문장)**으로 정리한다. **문제 정의 → 타겟 유저 → 해결 방법** 순서로 쓰면 깔끔. 기획의 첫 단추이자, **7주차 MVP 구현의 방향타**가 된다.

**팁**
- 혼자 고민하지 말고 AI에게 "나한테 질문 5개만 해줘"라고 요청 → 대답하다 보면 저절로 미션이 정리됨

- 옆 사람에게 읽어줬을 때 "아, 그래서 뭘 만든다는 거야?"가 나오면 다시 쓰기
- 3~5문장이 길면 AI에게 "더 짧게 줄여줘" 요청

# 📜 퀘스트

## 1. [Payment+File] 쇼핑몰 완성 (이미지 + 결제 + 마이페이지)
> 🎯 5주차 쇼핑몰에 **이미지 업로드 + 결제 + 마이페이지**를 붙여 진짜 서비스로 완성
> 💡 G1·G2 고블린을 하나로 합치고 **이미지 업로드**까지 얹은 종합 퀘스트

> ✅ **이미 고블린을 제출했다면, 이 퀘스트는 따로 제출하지 않아도 됩니다.**
> 결제 고블린(G1, 100원 결제)과 마이페이지 고블린(G2)을 제출한 분은 결제·마이페이지가 이미 완성된 상태라 **중복 제출 불필요**. 단, **고블린으로 제출하면 포인트가 더 높음** — 아직 안 했다면 고블린으로 완성 추천.

**전제 조건**
- ⚠️ 5주차 `[Auth + DB] 쇼핑몰 (결제 기능제외)` 퀘스트를 완료한 상태
- 토스페이먼츠 개발자 센터에서 테스트 키(`test_ck_...`)를 미리 발급

**미션**
- **Part 1 — 상품 이미지 업로드(관리자 기능)**
  - ImageKit으로 상품 이미지를 업로드하고 DB에 URL 저장
  - 상품 등록 화면에서 드래그앤드롭 또는 파일 선택으로 이미지 첨부
  - 상품 목록에 업로드된 이미지가 실제로 뜨는지 확인
- **Part 2 — 결제 플로우**
  - 장바구니 → 결제 페이지 이동
  - 토스페이먼츠 결제 위젯 붙이기(테스트 키)
  - 결제 승인 API는 **반드시 서버에서** 호출 (Secret Key 노출 금지)
  - 주문 정보를 DB `orders` 테이블에 저장
- **Part 3 — 마이페이지**
  - 로그인한 사용자의 주문 내역 조회 (상품명 / 금액 / 주문일 / 주문번호)
  - **본인 주문만** 볼 수 있도록 권한 제어
- **Part 4 — 배포**
  - Vercel에 배포하고 URL 제출
  - 환경변수(토스 Secret Key, ImageKit Key)는 **Vercel 대시보드**에 등록

**핵심 구조**
```
[관리자 상품 등록] → ImageKit에 이미지 업로드 → DB에 URL 저장
[장바구니] → [토스 결제 위젯] → 서버 승인 API → DB orders 저장
[마이페이지] → 본인 user_id로 orders 조회 → 주문 내역 렌더링
```

**DB 테이블 구조(참고)**
```
products 테이블:    id, name, price, image_url, description
orders 테이블:      id, user_id, total_price, paid_at, status
order_items 테이블: id, order_id, product_id, quantity, price
```

> 💡 **깨달아야 할 핵심**: 5주차까지 만든 쇼핑몰은 "가짜 쇼핑몰"이었다. 이번 퀘스트로 실제 돈이 흐르고(결제)·실제 파일이 저장되고(이미지)·내 주문 기록이 남는(마이페이지) 진짜 서비스의 뼈대를 완성한다. 토스 Secret Key는 절대 프론트엔드에 노출되면 안 됨 — 왜 승인 API를 서버에서 호출해야 하는지 자연스럽게 체득하게 된다.

**제출물**: 배포된 앱 URL(Vercel) · GitHub 저장소 링크 · 앱 스크린샷(상품 목록(이미지)→장바구니→결제→마이페이지 주문 내역) · **테스트 결제 성공 화면 스크린샷**

**포인트**: 기본 10(이미지 업로드+결제 성공+마이페이지 동작 & 배포 URL) / 에이전트 활용 5 / 창의 5(결제완료 이메일·주문 상태 관리·상품 검색·재고 관리 등) / 공유 5 → **올클리어 25pt**

**팁**
- 결제 플로우는 한 번에 성공하기 어려움 — 테스트 카드로 여러 번, 네트워크 탭 보는 습관. 에러 메시지를 에이전트에 그대로 붙여넣으면 대부분 해결
- 토스 공식 "결제 연동 가이드"를 먼저 훑고 시작
- 결제 성공 → 주문 저장 → 리다이렉트 **순서**가 꼬이면 주문 유실 — 트랜잭션 순서를 에이전트와 함께 정리
- 이미지는 공개 접근이 필요하니 Supabase Storage보다 **ImageKit**이 편함
- 마이페이지는 5주차 쇼핑몰의 "장바구니" 패턴 그대로 — `user_id` 필터만 걸면 끝

## 2. [Planning] 개인 프로젝트 기획서 2종 (MISSION / DEV)
> 🎯 개인 프로젝트를 **코딩하기 전에 기획서 2종을 먼저 완성**. `MISSION.md`(왜·무엇을 만들지)와 `DEV.md`(어떻게 만들지 — 개발 구조·TODO·외부 설정). 이 두 문서가 **7주차 MVP 구현의 방향타**가 된다.

**전제 조건**
- ⚠️ 만들고 싶은 개인 프로젝트 주제가 정해져 있어야 함(**앱 또는 에이전트** 중 선택). 아직 없다면 AI에게 "나한테 질문 5개만 해줘"로 주제부터 좁히기
- Claude Code에 **`dev-kickstart` 에이전트**가 설치되어 있으면 `DEV.md` 작성이 훨씬 수월

**미션**
- **Part 1 — `MISSION.md`: 왜 이걸 만드는가 (한 문단)**
  - **문제 정의 → 타겟 유저 → 해결 방법** 순서로 3~5문장
  - 타겟은 "전 국민"이 아니라 **구체적인 한 사람**(예: "같은 과 동기 민지")
  - 개인 경험에서 출발 — "나도 이거 없어서 힘들었다"가 가장 강력한 출발점
  - (보너스) 영어 한 줄 **Tagline**(예: "Notion for busy college students")
  - 💡 이미 **G3 [Mission] 한 줄 미션 쓰기** 고블린을 했다면 그 결과물을 그대로 가져오기
- **Part 2 — `DEV.md`: 어떻게 만들 것인가** (`dev-kickstart` 에이전트로 아래 3가지를 정리해 하나에 담기)
  - **① 개발 구조 선택** — 3가지 옵션 중 하나
    - **단일 파일**(`index.html` + `single.js`) — MVP·프로토타입에 최적, 가장 빠름
    - **Supabase 기반** — 로그인·DB가 필요할 때
    - **Next.js 풀스택** — 본격 프로덕션·SEO
  - **② TODO 리스트** — Phase 1 디자인/프로토타입 → Phase 2 기본 기능 → Phase 3 어려운 기능 → Phase 4 마무리 (각 Phase 끝에 체크포인트)
  - **③ 외부 설정 필요 항목** — API 키, DB URL, 환경변수 등을 표로 정리
- **Part 3 — GitHub 커밋**: `MISSION.md`와 `DEV.md`를 개인 프로젝트 저장소에 커밋 & 푸시

**핵심 구조**
```
[주제 정하기]
      ↓
[MISSION.md] — 왜 · 누구를 위해 · 무엇을 (한 문단)
      ↓
[dev-kickstart 에이전트]
      ↓
[DEV.md] — 개발 구조 + TODO + 외부 설정
      ↓
[GitHub 커밋] → 7주차 MVP 구현의 출발점
```

> 💡 **깨달아야 할 핵심**: 바로 코딩부터 시작하면 "뭘 만드는지"가 흐려지고 AI도 헤맨다. `MISSION.md`는 방향(왜), `DEV.md`는 지도(어떻게). 이 두 문서가 있으면 에이전트에게 "DEV.md의 Phase 2부터 시작하자"처럼 지시할 수 있어 7주차 구현 속도가 완전히 달라진다.

**제출물**
- GitHub 저장소의 `MISSION.md` + `DEV.md` 링크
- `MISSION.md` 내용 스크린샷 (문제 → 타겟 → 해결이 보이게)
- `DEV.md`의 개발 구조 선택 + TODO 리스트 스크린샷
- (보너스) `dev-kickstart` 에이전트와 대화한 스크린샷

**포인트**: 기본 10(`MISSION.md`·`DEV.md` 2종 커밋 & 링크 제출) / 에이전트 활용 5(`dev-kickstart` 등 에이전트와 2회 이상 대화하며 개선) / 창의 5(구체적 타겟·차별화가 살아있는 기획 & 현실적인 TODO) / 공유 5 → **올클리어 25pt**

**팁**

```

      ↓
[research.md 비교 리포트]
      ↓
[AUDIENCES.md 업데이트 — 경쟁사 약점 → 내 차별화]
```

> 💡 **깨달아야 할 핵심**: 기획은 진공 상태에서 하는 게 아니다. 경쟁 서비스의 유저들이 이미 있는데, 내 앱은 그들에게 뭘 더 줄 수 있는가? 크롬 MCP가 있으면 이 리서치를 30분 안에 끝낼 수 있다 — 수동 브라우징+복붙의 시대는 끝. 이 경험은 졸업 후 어떤 주제를 리서치할 때도 재활용할 수 있는 스킬이다.

**제출물**: GitHub의 `research.md` 링크 · 크롬 MCP가 캡처한 스크린샷 **3장 이상**(각 서비스당 1장) · AI와의 리서치 대화 스크린샷(최소 1장)

**포인트**: 기본 10(`research.md` 제출+3개 서비스 비교표+차별화 포인트 서술) / 에이전트 활용 5(크롬 MCP 자동 탐색 흔적: 스크린샷+대화 기록) / 창의 5(경쟁사 약점 인사이트·타겟 페르소나 스토리텔링·가격대 차별화 전략) / 공유 5 → **올클리어 25pt**

**팁**
- **가격 페이지**는 가장 솔직한 "유저에게 뭘 약속하는가" — 기능 페이지보다 가격 페이지를 먼저 분석하면 그 서비스의 본질이 보임
- AI에게 "이 서비스의 **약점 3가지**를 뽑아줘" → 내 차별화 포인트가 빠르게 보임
- 리뷰/앱스토어 별점/레딧의 불만 후기를 스크랩 → `AUDIENCES.md` 인풋이 풍부해짐
- 비교표는 Markdown 표 3열(서비스명) × 기능/가격/UX 3행 이상
- 차별화는 "더 많은 기능"이 아니라 **"다른 각도"**일 때 강력(예: 무료 / 한국어 / 더 작게 / 더 귀엽게)
